## 这条链路是怎么工作的

先说结构。这类专线 VPS 和普通香港 VPS 最大的区别在于它是「双端」的：你连接的是国内入口 IP，业务流量从境外出口 IP 发出去。以 MKCloud 的广港 IEPL 为例，链路是三段：

- **入口**：广州 BGP（多运营商接入），你的设备或服务器连这里；
- **跨境段**：广州到香港走 IEPL（International Ethernet Private Line，国际以太网专线），二层电路，不经过公网路由，官方标称端内延迟 1~2ms；
- **出口**：香港 BGP，你的程序在 VPS 里发起的访问都从这里出去。

每台 VPS 分配 1 个独立入口 IP 和 1 个独立出口 IP，这是商家官方文档明确写的，两类套餐（共享、独享）都一样。

为什么强调「广州 BGP 入口」？因为入口决定你从国内哪类网络接入。MKCloud 广港线的入口可选八线动态 BGP、电信、移动、联通或三线，BGP 入口的意义是不同运营商的用户都能就近接入，不用为电信、联通、移动分别操心路由。如果你团队在华南，这条线在物理距离上也是最短的广港链路之一。

顺带把三个容易混的概念理一下：

| 类型 | 工作方式 | 延迟参考 | 典型表现 |
| --- | --- | --- | --- |
| BGP 中转 | 走公网多线智能选路 | 看路由，波动较大 | 便宜，但跨境高峰容易拥堵 |
| IPLC | 点对点内网专线 | 沪港约 21ms | 稳定，距离 longer 延迟更高 |
| IEPL | 二层以太网专线 | 广港 1~2ms | 本主题主角，广港方向延迟最低 |

简单说：广州到香港这段，IEPL 是延迟最低的方案，端内延迟是个位数毫秒。但注意，这是「端内」数字，你的完整延迟还要加上本地到广州入口、香港出口到目标网站的耗时，后面细说。

## 流量计费还是独享带宽？

这是选档时最容易纠结的地方，官方知识库专门写过一篇对比，核心逻辑其实很简单：

- **流量计费**看峰值和月额度。峰值带宽高（150M 起步），但峰值不保证持续跑满，流量双向计算，超量暂停。适合间歇性访问、短时上传、日常办公这类「突发多、持续少」的业务。
- **独享带宽**看持续速率。速率恒定、不限流量，但数字上比共享峰值低很多。适合长时间推流、持续同步、定时大批量传输这类「一直跑」的业务。

官方给过一个对比例子（沪港线）：共享款 200Mbps 峰值 + 1024GB 月流量卖 288 元/月，独享 5Mbps 不限流量卖 388 元/月。200Mbps 和 5Mbps 对应的是两种完全不同的计费资源，不能直接说谁更快。广港方向同理：2TB 档（300M 峰值）和 20M 独享价格接近，选哪个完全取决于你的流量曲线是脉冲型还是恒定型。

还有个常见误会要澄清：「共享」指的是带宽模式，不是共享出口 IP。两类套餐每台 VPS 都有独立入口 IP 和独立出口 IP。不过官方也明确说了，独享 IP 不保证历史记录完全干净，也不保证平台账号不被限制——做电商多账号的朋友对这条要有合理预期。

## 延迟到底什么水平

官方标称广港 IEPL 端内延迟 1~2ms。第三方实测数据可以作个参考：有测评对 500GB 档做过测试，广州入口的 TCP ping 平均值电信约 34ms、联通约 33ms、移动约 38ms，香港出口本地延迟在 5ms 左右。

把这组数字拆开看就很清楚：你感觉到的延迟 = 本地到广州入口 + 端内 1~2ms + 出口到目标。华南宽带用户到广州入口本身就只有个位数到十几毫秒，所以华南用户全程体验最好；北方用户到广州入口可能就要 20~30ms，这时候沪港线（入口在上海）反而更合适。选线先看自己在哪，再看延迟数字。

另外提醒一句，标称的共享峰值带宽不要当成能持续跑满的承诺值，官方文档写得很直白：「共享带宽为峰值，不保证持续跑满」。

## 常见问题

**端内延迟 1~2ms，为什么我 ping 出来 30 多毫秒？**
1~2ms 只是广州入口到香港出口这段专线的延迟。你的完整延迟要加上本地到广州入口、香港出口到目标网站的路径，30 多 ms 属于正常范围。

**500GB 流量够用吗？**
按双向统计。有第三方测评算过，广港线的流量单价大约在每 GB（单向）0.7~0.8 元的量级，轻度办公和 API 请求够用，持续传输大文件就紧张了，建议先记录一周真实用量再选档。

**能换绑省份吗？**
可以。直连款绑定一个连入省份，绑定可自行切换，所以人在哪里变动影响不大。

**支持哪些支付方式？**
支持支付宝，月付起购，现货自动开通。

**降级套餐退差价吗？**
不退。升级、降级都通过工单处理，是否保留 IP、是否迁移以工单结果为准。
